# 要件定義：台本スライド出し・守山2画面・Stream Deck

版：1.0（2026-11-19）　対象：`STADIUMVISION野球システム`（ポート3007）
担当：要件定義・品質管理＝Opus／実装＝Sonnet

---

## 0. 背景と目的

MLB CUP 2026 守山市民球場の大型ビジョン運用。昨年は「式次第（キュー一覧）」を手で組んでいたが、
今年は**MCの台本（Excel）を読み込み、台本を追いながらスライド・BGMを出せる**ようにする。
あわせて出力を**守山の2画面構成（16:9出力の中の14:5の帯）**に固定し、**Stream Deck（15キー）で操作**できるようにする。

## 1. 用語

| 用語 | 意味 |
|---|---|
| 帯（band） | 1920×1080 出力のうち、球場ビジョンに映る範囲。**y=197、高さ686**（1920×686＝14:5）。上下197pxは黒（スケーラーが切り取る） |
| 左面 | 帯の左半分 960×686。スライド／バナーを出す |
| 右面 | 帯の右半分 960×686。**遊撃カメラ**の生映像（キャプチャーボード） |
| フタ | ロゴ画面。何も出さないときの「ふた」。左面だけロゴ（＝左フタ）と、帯全体ロゴ（＝全面フタ）の2種 |
| 台本 | MCの進行台本（Excel）。1行＝1つの進行（時刻・内容・BGM・ビジョン・MIC・話者・セリフ・備考） |
| キュー | 台本の行にひもづけた「出すもの」（左面の素材・右面の素材・BGMの操作） |
| 読み位置 | オペレーターがいま追っている台本の行（キューを出さずに動かせる） |

## 2. 既存機能（壊さないこと）

- 音楽バー（`js/music_admin.js`）：曲ボタンでのポン出し、STOP（フェード）、くり返し、音量、出力先
- PREVIEW / ON AIR の2モニター、TAKE、BLACK、カット／フェード、テスト画面、左右入れ替え（swap）
- 出力の形（`state.output`：wide＝32:9 ／ sdi＝帯）、HDMI出力スクリプト、OBSの透明カメラ枠（`camera=obs`）
- 選手スライド・名簿・HRダービーのカウンター
- `/api/control`（Stream Deck のHTTP操作）既存の action はそのまま動くこと
- 依存パッケージなし（Node 標準モジュールのみ）。`data/state.json` への保存・再起動で再開

## 3. 機能要件

### F1. 守山2画面の出力（既定）

- F1-1 出力の形の既定を **sdi・bandY=197・bandH=686** にする（新規の state.json のとき。既存の保存値は尊重）。
  設定タブに「守山（197／686）」の**ワンクリックのプリセット**を置く。
- F1-2 帯のレイアウトは「左右2分割（960×686 ×2）」を既定にし、**右面の既定は camera（cam1）**。
- F1-3 左面にスライド、右面にカメラ、のほか、帯全体に1枚（全面フタなど）も出せること（既存の「帯 一枚」）。
- F1-4 OBS 経由（`camera=obs`）でも右面が透明枠になること（既存仕様の確認）。

### F2. フタ（ロゴ画面）

- F2-1 「左フタ」：左面をロゴ素材にする（右面はそのまま）。「全面フタ」：帯全体をロゴ素材にする。
- F2-2 ロゴ素材は設定で選ぶ（`slides/` 内の画像）。既定は `slides/フタ/` 内の最初の画像（無ければ黒＋注意表示）。
  左フタ用（960×686）と全面フタ用（1920×686）を別々に設定できる。
- F2-3 フタは**本線に直接出す**（ワンボタン）。もう一度押すと直前の画面に戻る（トグル）。
- F2-4 BLACK とは別物（BLACK は帯全体を黒、フタはロゴ）。

### F3. 台本の読み込み

- F3-1 管理画面の新タブ「**台本**」に、`.xlsx` のファイル選択（ドラッグ＆ドロップ可）を置く。
  補助として `.csv` / `.tsv` と「貼り付け（タブ区切り）」も受ける。
- F3-2 `.xlsx` は**サーバー側で、Node 標準の `zlib.inflateRawSync` で解凍し、XML を自前で読む**（依存なし）。
  - 対象：`xl/workbook.xml`（シート名と順番）、`xl/_rels/workbook.xml.rels`、`xl/sharedStrings.xml`（rich text の `<r><t>` 連結を含む）、`xl/worksheets/sheetN.xml`（`t="s"`／`t="inlineStr"`／`t="str"`／数値）。
  - セル内改行・`&amp;` などの実体参照を正しく戻す。セル位置（`r="C5"`）で列を決め、空セルの抜けに強いこと。
  - ZIP の data descriptor（ローカルヘッダのサイズ0）にも対応するため、**セントラルディレクトリからサイズを読む**。
  - 上限：ファイル 20MB、シート 30、1シート 3000 行、1セル 5000 文字。超えたら日本語で理由を返す。
- F3-3 **シート＝セクション**（例：開会式／HRD／決勝／閉会式）。全シートを読み、セクションとして並べる。
- F3-4 **見出し行の自動検出**：各シートの先頭20行から、既知の見出し語を2つ以上含む行を見出しとする。
  見出し語（大文字小文字・全角半角・前後空白を無視）：

  | 役割 | 見出し語の例 |
  |---|---|
  | time 時刻 | 時刻, TIME, 時間 |
  | dur 経過 | 経過, 尺 |
  | title 内容 | 内容, 項目, 進行 |
  | bgm 音 | BGM, MUSIC, 音源, 音響, 音楽 |
  | vision ビジョン | ビジョン, VISION, 映像, 大型ビジョン |
  | mic マイク | MIC, マイク |
  | speaker 話者 | MC, 話者, 担当 |
  | script セリフ | SCRIPT, セリフ, 台詞, 原稿, コメント |
  | note 備考 | 備考, 動線, 演出 |

  - 見出しが空の列や「コメント」のように意味が揺れる列があるため、**自動判定の後に「列の割り当て」画面**でシートごとに直せること（プルダウン）。
  - 自動判定の補正：script 候補が複数あるときは**平均文字数が最も長い列**を script、短い方を speaker にする
    （例：昨年の開会式シートは「コメント」列＝話者名、見出し空欄の列＝セリフ）。
  - 見出しが見つからないシートは、1列目＝title、最長列＝script として仮割り当てし、画面で直せる。
- F3-5 行の取り込み：見出しより下の行を、空行を除いて `{section, time, dur, title, bgm, vision, mic, speaker, script, note}` にする。
  「↓」「以下、繰り返し」「〃」は**前の行と同じ**の意味として表示上そのまま残す（キューの推定では「変更なし」扱い）。
- F3-6 読み込み直し：同じ台本を読み直すとき、**既にひもづけたキューは、セクション名＋行の内容（title＋scriptの先頭）が一致する行に引き継ぐ**。引き継げなかったキューは一覧で知らせる。
- F3-7 台本とキューは `state.json` に保存する（個人名を含むため `data/` は公開しない＝既存の .gitignore のまま）。

### F4. キューのひもづけ（編集モード）

- F4-1 台本の各行に「キュー」を付け外しできる。キューの中身：
  - 左面：なし（変えない）／スライド（`slides/` から選ぶ）／左フタ／黒
  - 右面：なし（変えない）／カメラ（cam1/cam2）／スライド／黒
  - 帯全体：全面フタ／スライド（1920×686）を使う場合は左右より優先
  - BGM：なし／再生（曲・くり返し有無）／フェードアウト／即停止
  - メモ（任意）
- F4-2 **自動の提案**（確定ではなく「提案」として薄く表示し、ワンクリックで採用）：
  - BGM 列：`『曲名』` を `music/` の曲名と照合（部分一致・全角半角無視）→ 再生。`ループ` を含めば くり返し。
    `FADE OUT` `Fade Out` `F.O.` `FO` `フェードアウト` → フェードアウト。`STOP` `停止` `無音` → 停止。
  - ビジョン列：`ロゴ` → 左フタ、`ライブカメラ` `カメラ` → 右面カメラ。
  - 内容（title）：`slides/` のファイル名（番号・拡張子を除く）と照合して一致すれば左面スライドを提案（例：「選手宣誓」→ `slides/進行/07_選手宣誓.png`）。
- F4-3 一括操作：「提案をすべて採用」「このセクションのキューを全部消す」。
- F4-4 既存の「式次第」タブは**台本に統合**する。既存 state の `cues` は「手動の式次第」セクションとして台本の先頭に移す（移行処理）。`/api/control` の `cue`/`next`/`prev` はキュー付きの行に対して動く。

### F5. 本番モード（台本を追ってスライドを出す）

- F5-1 台本タブを「本番」に切り替えると、行の一覧が**大きめの文字で読み原稿のように**並ぶ。
  列：時刻／内容／BGM／ビジョン／話者／セリフ（折り返し）／キューのバッジ。
- F5-2 **読み位置**（青）と **ON AIR のキュー**（赤）と **次のキュー**（黄）を色で示す。読み位置は画面の上から1/3に来るよう自動スクロール。
- F5-3 操作：
  - **NEXT**：読み位置より後で最初のキュー付きの行を本線に出し（左右の素材＋BGM）、読み位置をその行へ。
  - **PREV**：1つ前のキュー付き行を出し直す（BGMは鳴らし直さない＝確認ダイアログなし、映像だけ戻す）。
  - **読み位置 ↓／↑**：キューを出さずに1行ずつ動かす（キーボード ↓↑、Stream Deck）。
  - 行をダブルクリック：その行のキューを出す（キューが無い行なら読み位置だけ移す）。
  - セクションの見出しでジャンプ。
- F5-4 PREVIEW には常に「次のキュー」の画面を出す（既存の PVW の仕組みを使う）。
- F5-5 キューを出すときの BGM は音楽バーと同じ再生系を使う（二重再生しない。再生中の別曲はフェードしてから次）。
- F5-6 本番中に誤って台本を編集しないよう、本番モードでは編集UIを隠す。

### F6. Stream Deck（USB直結・機種自動判別・ボタン自動割り当て）

- F6-1 テロップシステム（`BASEBALLテロップシステム/js/baseball_dashboard.js` の「Stream Deck USB直接接続」部）と同じ方式：**WebHID**（Chrome / Edge）で直接つなぐ。
  機種表（product ID → 列数・行数・キー数・画像形式・アイコン寸法・入力オフセット）も同じものを使う。
  - 初回は「Stream Deck を接続」ボタン（ユーザー操作が必要）。2回目以降は `navigator.hid.getDevices()` で**自動再接続**。抜き差し（`connect`/`disconnect`）にも追従。
  - WebHID が無いブラウザでは、ボタンを出さず「Chrome / Edge で開いてください」と表示。
- F6-2 **キーのLCDに絵を描く**（ラベル・色）。状態を反映して描き直す（ON 中は明るい色、OFF は暗い色）。描画は変化があったキーだけ。
- F6-3 **15キー（5×3）の割り当て（本命）**：

  | | 1 | 2 | 3 | 4 | 5 |
  |---|---|---|---|---|---|
  | 上段 | **NEXT ▶**（次のキュー名を表示） | **◀ PREV** | 読み位置 ↑ | 読み位置 ↓ | **TAKE**（PVW→本線） |
  | 中段 | **左フタ**（ON中は点灯） | **全面フタ**（ON中は点灯） | 右面 カメラ⇔ロゴ | ⇄ 左右入れ替え | **BLACK**（ON中は赤） |
  | 下段 | BGM 1 | BGM 2 | BGM 3 | **BGM フェードアウト** | **BGM 即停止** |

  - BGM 1〜3 は音楽バーの先頭3曲（曲名をキーに表示。鳴っている曲は点灯）。設定で別の曲に差し替え可。
- F6-4 **他機種は自動で割り当て**（優先順位の高いものから詰める）：
  - 優先順位：NEXT, PREV, 左フタ, BLACK, BGMフェード, BGM停止, 全面フタ, TAKE, 読み位置↓, 読み位置↑, 左右入れ替え, 右面カメラ⇔ロゴ, BGM1, BGM2, BGM3, 以降 BGM4〜…, セクションのジャンプ
  - 6キー（Mini）：上位6つ。8キー（+）：上位8つ。32キー（XL）：15キーの割り当て＋BGM4〜12＋セクションジャンプ。
- F6-5 Stream Deck の操作は、管理画面のボタンと**同じ関数**を呼ぶ（動きを一致させる）。
- F6-6 HTTP（Elgato 公式アプリの「Webサイトを開く」等）からも同じ操作ができるよう、`/api/control` に action を追加：
  `futa`（左フタ トグル）、`futaFull`（全面フタ トグル）、`readNext`・`readPrev`（読み位置）、`musicFade`（フェードアウト）。
  管理画面が必要な操作（BGM・読み位置）は、既存の `take` と同じく「管理画面へコマンドを送る」方式。

### F7. 管理画面のレイアウト

- 既存の「スクロールなし1画面・PREVIEW と ON AIR を同時に見る」方針を守る。
- 台本タブは、左＝台本の一覧（スクロール可）、右＝PREVIEW／ON AIR の縮小モニター。モニターは帯の形（14:5）で表示。
- 1920×1080 のノートPC画面で、台本の文字が 16px 以上で読めること。

## 4. 非機能要件

| 項目 | 要件 |
|---|---|
| 依存 | npm パッケージ不可。Node 標準モジュールと素のブラウザJSのみ |
| 安定性 | 台本の読み込み失敗・Stream Deck の切断・曲が無い等で**本線を止めない／サーバーを落とさない**。エラーは日本語で画面に出す |
| 入力チェック | 台本・キューは server 側で検証（既存 `validateState` の流儀）。不正なら保存しない |
| 性能 | 3000行の台本で、NEXT から本線切り替えまで 200ms 以内。一覧の描画で固まらない |
| 保存 | 既存どおり `data/state.json` へ原子的保存。再起動後に台本・キュー・読み位置が戻る |
| 個人情報 | 台本（人名・選手名）は `data/` のみ。リポジトリに入れない |
| 文言 | 画面の文字・エラーは日本語。専門用語を避ける |
| 互換 | 既存の state.json（cues あり）を読み込めること（移行） |

## 5. 受け入れ試験（品質管理でOpusが確認する項目）

1. 新規起動で、出力が sdi・197／686・左右2分割・右面カメラになっている
2. 昨年の台本と同じ形の `.xlsx`（開会式：時刻,経過,内容,BGM,ビジョン,MIC,コメント,(空),備考／HRD：時刻,内容,BGM,ビジョン,MC,コメント／決勝：TIME,MUSIC,SCRIPT／閉会式：内容,BGM,ビジョン,MC,コメント、セル内改行・rich text・空列あり）を読み込み、4セクション・全行が正しい列で取り込まれる
3. 開会式シートで、セリフが空見出しの列から取られ、話者が「コメント」列から取られる（自動補正）
4. BGM 列の `『入場　マーチングバンド』 ループ再生` が music の曲に照合され、`FADE OUT` がフェードに、`無音` が停止になる提案が出る
5. NEXT で、キュー付き行が順に本線に出る。PVW に次のキュー。BGM が鳴る／フェードする
6. 読み位置↓↑でキューが出ないこと。行ダブルクリックでそのキューが出ること
7. 左フタ・全面フタがトグルで出入りし、直前の画面に戻る。BLACK と独立
8. 台本の読み直しでキューが引き継がれ、引き継げない分が知らされる
9. 既存の cues 入り state.json が移行される。既存の `/api/control?action=next` 等が動く
10. Stream Deck（モックのHIDデバイス）で、15キー・6キー・32キーそれぞれ自動割り当てされ、押下で同じ関数が呼ばれ、LCD描画データが送られる
11. 壊れた xlsx・巨大ファイル・シート無し・見出し無しで、日本語のエラーが出てサーバーが落ちない
12. 既存機能（音楽バー、TAKE、BLACK、選手スライド、テスト画面、HDMI出力）が引き続き動く
